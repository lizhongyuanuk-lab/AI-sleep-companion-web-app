# Stage 5 Page Wiring Map

## Scope Notes

Stage 5 page wiring must preserve Stage 3 product truth and Stage 4 architecture truth. Existing `src/` files are implementation inventory only. Every page rule below cites its source document by filename.

Route labels in this document follow the requested Stage 5 planning set. Stage 3 canonical route logic names `"/home"` and the repository source map names the sleep page route as `"/sleep-monitoring"`. Therefore the requested `"/sleep"` row is a planning label for the Sleep page only; adding a new runtime `"/sleep"` route is a follow-up requiring product approval.

## Cross-Page Contract Guardrails

| Guardrail | Source | Required Stage 5 handling |
| --- | --- | --- |
| `OnboardingPreset` lifecycle | `data-contract.md`, `product-logic.md` | Persisted statuses are `active`, `consumed`, `expired`; `stale` is derived. |
| Home CTA to Talk | `data-contract.md` | Normal Stage 3 Home CTA target is exactly `"/talk"` with required `TalkEntryContext`. |
| Room selection handoff | `page-logic/room.md` | Full active preset must be carried when present; do not rebuild a different preset later. |
| Memory actions | `product-logic.md`, `page-logic/memory.md` | Only Agree, Disagree, Hide. Hide excludes from personalization. |
| Sleep suggestion | `product-logic.md`, `page-logic/sleep-monitoring.md` | User-entered `SleepLog` and traceable `SleepInsight`; no passive monitoring. |
| Mock behavior | `coding-architecture-rules.md` | Label every mock/local source and document unresolved real backend dependencies. |
